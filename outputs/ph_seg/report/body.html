PHI Border Refinement

Nine ways of snapping Priority Habitat polygons to what the satellite image actually shows, tested on 96 polygons across six sites — and the ensemble we recommend running.

RecommendationEnsemble (pixel majority vote) of grabcut2 + sam2iter + sam2tile, run inside a tolerance band of ±15 m (shrunk to ±4–15 m for thin polygons), followed by overlap resolution and 0.6 m simplification.
Best singlesam2iter (SAM 2.1 large, box + points + the polygon as mask prompt, 3 iterations) — cleanest object-like edges; grabcut2 is the strongest non-neural method and runs on CPU in ~2 s per polygon.
DroppedRandom walker, marker watershed, geodesic active contours, SLIC superpixels + kNN, per-polygon random-forest, SAM auto-masks-as-superpixels — each fails on some habitat type (details below).
Outputsoutputs/ph_seg/refined_polygons/<site>_refined_{vote,grabcut2,sam2iter,sam2tile}.geojson — original attributes kept, EPSG:27700. Code in scripts/ph_seg/.

What we started from

Six PHI extracts (Sep 2025 version) over WorldView Legion / WV‑03 / Pléiades Neo / VS30 imagery at 0.19–0.40 m, four‑band R,G,B,NIR (Essex is RGB only). 98 polygons in total: 40 deciduous woodland (NFI 2023 source), 26 reedbed/fen (Millbrook), 32 grassland and other parcels. Two Blenheim woodland polygons fall entirely outside the imagery footprint and were skipped; the imagery is clipped to an AOI, so wherever a polygon leaves the footprint the original geometry is retained unchanged and only the part inside the image is refined.

The kind of imprecision we see is consistent: woodland edges drawn 5–20 m inside or outside the visible canopy, grassland parcels drawn as straight-sided admin shapes that cut across hedges, reedbed outlines that predate the current pond edges, and a few polygons that are simply misplaced (e.g. Millbrook #20 "woodland" sits on grass between two tree lines). We treat the last group as out of scope: a border-refinement method should not move a boundary 50 m.

Ground rules that every method shares

  • Tolerance band. The polygon eroded by d is a fixed "core" (always inside); everything beyond the polygon dilated by d is fixed "outside"; only the ring in between is up for grabs. Default d = 15 m; for thin polygons d shrinks to clip(0.4 × mean width, 4, 15) so hedgerow-woods and slivers cannot balloon.
  • Same features. R,G,B,NIR (or ExG for RGB-only), NDVI and a 5×5 texture band, at native resolution up to a 2048 px working window.
  • Same clean-up. Opening/closing with a 2 px disc, hole filling and speck removal at 0.2 % of the polygon area, then re‑imposing core/outside.
  • Topology. Neighbouring polygons are refined independently, then any pixel claimed twice goes to the polygon whose original contained it (or the nearest original). Originals do not overlap in any site.
  • Semantics. We aim for the boundary that is visible in the image — the canopy edge, the grass/hedge edge, the reed/water edge — not the OS field-boundary centreline. Hedges therefore tend to end up outside grassland parcels.

How the methods compare

There is no ground truth here, so the numbers are proxies computed on every polygon (n = 96, d = 15 m); the pictures are what actually decided the ranking.

  • contrast — mean feature difference between a 3 m inner ring and a 3 m outer ring along the new border, in pooled‑std units. Higher = the border separates two visibly different surfaces.
  • edge_pct — percentile of image gradient magnitude under the border. Higher = border sits on edges (but watershed shows this can be gamed).
  • iou_orig / area_ratio — how far the polygon moved. Neither should be extreme.
  • compact — perimeter² / 4πA; large values mean ragged borders.

Recommended pipeline

  1. Clip each polygon to the imagery footprint; keep the outside part verbatim.
  2. Build the tolerance band with adaptive d (--adaptive).
  3. Run grabcut2 (CPU), sam2iter and sam2tile (GPU, ~2 GB).
  4. Pixel majority vote at 0.5 m, resolve overlaps between neighbours, simplify at 0.6 m.
cd scripts/ph_seg
python run_refine.py --methods orig,grabcut2 --adaptive --tag final          # CPU
python run_refine.py --methods sam2iter,sam2tile --adaptive --tag final      # GPU
python postprocess.py --tag final --vote grabcut2,sam2iter,sam2tile --methods grabcut2,sam2iter,sam2tile,vote
python overview.py --tag final --method vote_final; python panels.py --tag final --sites <site> --pids 1,2 --methods orig,vote_final

Whole run: ~40 min for 96 polygons with the GPU shared with another job; SAM 2.1 large is fetched from HuggingFace (facebook/sam2.1-hiera-large) on first use. GrabCut alone (no GPU) is a respectable fallback and takes ~3 min.

Caveats and what to do next

  • Validation. All ranking is by proxy metrics plus visual inspection. Hand‑digitising 20–30 reference borders (mix of woodland, grassland, reedbed) would let us report a real boundary‑distance error and tune d and the vote threshold properly.
  • Hedge in or out. Grassland parcels now stop at the grass edge. If the intended convention is the hedge centreline, buffer the grassland classes by half a hedge width (~2–3 m) afterwards, or add hedge pixels back where the original included them.
  • Misplaced polygons. Where the PHI outline is >d off (Millbrook #20, some Northfield slivers) refinement cannot fix it; the band keeps the damage bounded. A "confidence" flag (IoU between the three voters) would surface these for a human.
  • Resolution. Whole‑window SAM downsamples large polygons to 1024 px (~0.7 m/px at Northfield); the tiled variant works at native resolution and is the one to extend if finer edges are needed.
  • Determinism. OpenCV GrabCut seeds its GMM with k‑means++; the RNG is now seeded so runs are reproducible.
  • Not tried. Foundation‑model features (DINOv2/v3) with label propagation — patch size ≈5 m at this GSD makes them a poor fit for edge work; a fine‑tuned SAM decoder would help but was out of scope (no training).
